# 视频号素材归档系统运行维护手册

这份文件记录当前系统的真实运行结构、配置位置、入口关系和排错顺序。以后遇到“公众号不回复”“企业微信客服不回复”“下载链接过期”或“网页打不开”，先从这里开始查。

系统只用于归档本人或已经获得授权的公开普通视频素材。当前解析层仍是内部验证版本，正式对外运营前必须替换为自研或已经获得商业授权的解析服务。

## 2. 三个用户入口

### 2.1 公众号直聊：当前主入口

用户关注公众号后，在公众号对话框粘贴视频号复制链接。公众号返回一个 10 分钟有效的短下载链接。

```text
视频号 -> 分享 -> 复制链接
-> 发送给公众号
-> 微信公众平台 POST /api/wechat/callback
-> 服务器解析视频信息
-> 创建 /d/<ticket> 短链接
-> 公众号被动回复短链接
-> 用户点击下载 作者_标题.mp4
```

公众号消息回调：

```text
https://saveclip.cn/api/wechat/callback
```

对应代码：

```text
src/wechat-official.js
src/download-ticket.js
```

### 2.2 H5 页面：网页兜底入口

用户可以直接打开网页，粘贴视频号分享链接并下载。

```text
https://saveclip.cn
```

链路：

```text
H5 粘贴链接
-> POST /api/fetch_video_profile
-> 服务器解析视频信息
-> 创建带 HMAC 签名的 /api/download?... 地址
-> 浏览器点击下载命名文件
```

对应代码：

```text
src/index.html
server.js
src/download-link.js
```

### 2.3 企业微信客服：备用入口

正式客服入口：

```text
https://saveclip.cn/contact
```

该地址不会显示页面，而是 `302` 跳转到企业微信官方客服链接。公开二维码保存在：

```text
artifacts/saveclip-wecom-contact-qr.png
```

用户进入后看到的客服账号名称应为：

```text
创作者素材归档助手
```

链路：

```text
用户扫描二维码或打开 /contact
-> 进入“创作者素材归档助手”
-> 用户发送视频号复制链接
-> 企业微信推送回调事件
-> POST /api/wecom/app-callback
-> 使用回调 Token 和固定 WECOM_OPEN_KFID 调用 kf/sync_msg
-> 拉取用户消息
-> 解析视频信息
-> 创建带签名的 /api/download?... 地址
-> 调用 kf/send_msg 回复用户
```

对应代码：

```text
src/wecom-callback.js
src/wecom-kf.js
```

注意：

- “创作者素材归档助手”是当前 API 管理的客服账号。
- 正确入口只有两个：扫描 `artifacts/saveclip-wecom-contact-qr.png` 二维码，
  或在微信中打开 `https://saveclip.cn/contact`（302 跳转到官方客服链接）。
- 微信里”郑州赤兔网络有限公司”联系人列表中的”郑州赤兔网络有限公司客服”
  以及任何名称不是”创作者素材归档助手”的入口，消息不会进入代码管理的队列，
  不会触发自动回复。
- 企业微信客服是备用链路。公众号直聊仍是当前主入口。

## 4. 解析层

解析适配器位于：

```text
src/adapters/
```

入口文件：

```text
src/adapters/index.js
```

选择逻辑：

```text
如果配置 PROFILE_API_URL
-> 使用 src/adapters/custom-api.js

否则
-> 使用 src/adapters/prototype.js
```

`custom-api.js` 是未来接入自研或已授权解析服务的位置。请求格式：

```http
POST PROFILE_API_URL
Content-Type: application/json
Authorization: Bearer PROFILE_API_TOKEN

{"url":"https://weixin.qq.com/sph/..."}
```

`PROFILE_API_TOKEN` 可选。如果上游需要鉴权再填写。

`prototype.js` 仅用于内部验证。它不适合公开收费运营，也不应被当作长期稳定接口。正式产品上线前，必须换成自研或已获得商业授权的解析服务。

## 5. 下载层

### 5.1 视频选择

视频选择逻辑位于：

```text
src/lib.js
```

优先级：

```text
H.264 -> H.265 -> 默认地址
```

优先使用 H.264 是为了提高 iPhone 兼容性。

### 5.2 下载代理

服务器不会长期保存视频。用户点击下载时，服务器临时代理允许范围内的视频 CDN：

```text
finder.video.qq.com
```

代码只允许符合规则的 HTTPS 视频地址，并限制跳转次数，避免将下载接口变成任意 URL 代理。

### 5.3 文件命名

文件名规则：

```text
作者_标题.mp4
```

逻辑位于：

```text
src/lib.js
```

服务端通过 `Content-Disposition` 返回 UTF-8 文件名。保存到 iPhone“文件”App 时通常会保留名称；保存到“照片”App 时，iOS 通常不展示原始文件名。

### 5.4 两种下载链接

H5 和企业微信客服使用签名下载链接：

```text
/api/download?url=...&author=...&title=...&expires=...&sig=...
```

签名逻辑：

```text
src/download-link.js
```

公众号使用短下载链接：

```text
/d/<ticket>
```

短票据逻辑：

```text
src/download-ticket.js
```

原因：公众号聊天窗口可能截断过长 URL。短票据默认 10 分钟有效，最多在内存中保存 5000 条。

当前限制：

- 短票据保存在 Node 进程内存。
- 服务重启后，已经发出的 `/d/<ticket>` 会失效。
- 多实例部署前应将短票据迁移到 Redis。

## 11. 常见故障排查

### 11.1 网页打不开

按顺序检查：

1. `dig +short saveclip.cn` 是否能查到服务器 IP。
2. `curl -fsS https://saveclip.cn/health` 是否返回 `{"ok":true}`。
3. `sudo systemctl status channels-archive.service` 是否为 `active`。
4. `sudo nginx -t` 是否通过。
5. 腾讯云安全组是否允许 `80` 和 `443`。

### 11.2 H5 可以打开，但解析失败

按顺序检查：

1. 用户发送的是否是 `https://weixin.qq.com/sph/...` 链接。
2. `PROFILE_API_URL` 对应的解析上游是否可用。
3. `PROFILE_API_TOKEN` 是否过期。
4. `journalctl` 是否出现上游 `401`、`403`、`429` 或 `5xx`。
5. 视频是否属于当前支持的公开普通视频类型。

### 11.3 公众号没有回复

按顺序检查：

1. `https://saveclip.cn/health` 是否正常。
2. 公众号后台消息推送是否仍为启用状态。
3. Nginx 是否收到 `POST /api/wechat/callback`。
4. `.wechat-official.env` 中 Token 是否与公众号后台一致。
5. `journalctl` 是否出现“公众号回调签名无效”。
6. 解析上游是否超时，导致没有在规定时间内完成被动回复。

### 11.4 企业微信客服没有回复

按顺序检查：

1. 用户是否通过正式二维码或 `https://saveclip.cn/contact` 进入“创作者素材归档助手”。
2. Nginx 是否收到 `POST /api/wecom/app-callback`。
3. `journalctl` 是否出现 `invalid open_kfid`。
4. `.wecom-kf.env` 是否存在 `WECOM_OPEN_KFID`。
5. `WECOM_OPEN_KFID` 是否仍对应企业微信官方账号列表里的“创作者素材归档助手”。
6. 应用 Secret 是否有效，企业可信 IP 是否仍包含服务器 IP。
7. 企业微信客服账号是否仍处于“通过 API 管理”状态。
8. 至少一名企业微信成员是否正常登录企业微信 App。

真实故障记录（按时间倒序）：

```text
现象：企业微信客服收到消息后报 ReferenceError: content is not defined，
     无法回复任何消息。
原因：修复游标 bug 时，let content; 声明被错误地放入
     loadCustomerServiceCursor 函数内部，而非 replyToMessage 内部，
     导致 replyToMessage 执行到赋值语句时变量未定义直接抛错。
修复：将 let content; 移至 replyToMessage 函数内 try 块之前。

现象：企业微信客服回复了下载链接，但链接过长导致微信截断，点击报错。
原因：wecom-kf.js 使用的是带签名参数的长链接（/api/download?...），
     而公众号已改用短票据链接（/d/<ticket>），企业微信客服漏掉了同样的改动。
修复：wecom-kf.js 改为调用 createDownloadTicket，回复短链接。

现象：企业微信客服能收到消息，但不回复。
原因 1：kf/sync_msg 请求使用了回调中的异常客服 ID。
修复 1：通过官方 kf/account/list 查询有效客服账号，
       将”创作者素材归档助手”的账号 ID 写入 WECOM_OPEN_KFID，
       同步时优先使用该固定值。

原因 2：企业微信回调事件偶尔早于客服消息正式进入同步队列。
       回调触发后立即调用 kf/sync_msg，可能暂时得到空列表。
修复 2：收到回调后增加短暂延迟重试；
       仍为空时，再执行一次官方允许的不带回调 Token 的兜底补拉。

原因 3：kf/sync_msg 返回 next_cursor，但旧代码没有持久化读取进度。
       每次回调都从空游标开始，重复读取历史消息，无法稳定读取新消息。
       重复回复还可能触发 send msg count limit。
修复 3：将 next_cursor 持久化到 .wecom-kf.cursor；
       回调串行处理；首次启动只建立最新游标，不回复历史消息；
       正常运行时先保存游标再处理回复。
```

企业微信官方规则：用户每主动发送一次消息，客服在 48 小时内最多主动回复 5 条。若日志出现 `send msg count limit`，先停止重复测试，确认游标修复已经部署，再由用户发送一条新消息重新开启回复额度。

### 11.5 点击下载提示“下载链接已过期”

公众号短链接：

1. 确认链接形式为 `/d/<ticket>`。
2. 确认是否超过 10 分钟。
3. 确认 Node 服务是否刚刚重启。
4. 当前短票据存在内存中，重启后旧链接必然失效。

H5 或企业微信客服签名链接：

1. 确认地址包含 `expires` 和 `sig`。
2. 检查链接是否被聊天窗口截断。
3. 检查 `DOWNLOAD_SIGNING_SECRET` 是否被修改。
4. 确认链接是否超过 10 分钟。

### 11.6 下载成功，但文件名不对

检查：

```text
src/lib.js
createDownloadFilename()
```

文件名依赖解析结果中的作者昵称和视频描述。如果上游没有返回标题，系统会使用默认名称。

```text
/home/ubuntu/channels-archive-worker
```

然后执行：

```sh
sudo systemctl restart channels-archive.service
curl -fsS https://saveclip.cn/health
sudo journalctl -u channels-archive.service --since "5 minutes ago" --no-pager
```

如果 SSH 连续出现：

```text
Connection closed by SERVER_IP port 22
```

不要高频重试。等待几分钟后再使用单次 SSH 连接，避免继续触发服务器登录限流。

## 13. 密钥管理

必须遵守：

- 真实 Token、Secret、AESKey、Cookie 和服务器密码只保存在服务器环境文件或本地受保护文件中。
- 环境文件权限使用 `600`。
- 环境文件已经加入 `.gitignore`。
- 教程、截图和聊天记录中不要出现真实密钥。
- 密钥意外出现在截图或聊天记录后，应及时轮换。

检查权限：

```sh
chmod 600 .env .wechat-official.env .wecom-app-callback.env .wecom-kf.env .wecom-contact.env
```

## 14. 正式运营前必须完成

当前系统可以继续用于内部学习交流和授权素材归档验证，但不应直接作为收费产品发布。

正式运营前至少需要：

1. 将 `src/adapters/prototype.js` 替换为自研或已获得商业授权的解析服务。
2. 使用 Redis 保存下载短票据。
3. 增加单用户、单 IP 和全局限流。
4. 增加授权记录和审计日志。
5. 增加日志脱敏、监控和告警。
6. 增加隐私政策、服务条款、投诉下架和封禁机制。
7. 轮换曾经出现在聊天或截图中的 Token、Secret 和 AESKey。
